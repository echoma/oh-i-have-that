# 前端构建和部署说明

## 📁 目录结构说明

### ✅ 正确的前端目录：`frontend/`
- **源码目录**：`frontend/src/`
- **构建脚本**：`frontend/build.js`
- **配置文件**：`frontend/package.json`
- **输出目录**：`frontend/dist/` ← **这是正确的静态文件目录**

### ❌ 已废弃的目录：`static-website/`
- 这个目录包含的是简单的HTML文件
- 不应该再使用，建议删除
- 所有Terraform配置已更新为使用 `frontend/dist/`

## 🚀 前端构建流程

### 1. 安装依赖
```bash
cd frontend
npm install
```

### 2. 开发模式
```bash
npm run dev        # 构建并启动开发服务器
npm run serve      # 仅启动服务器（端口8080）
npm run watch      # 监听文件变化自动构建
```

### 3. 生产构建
```bash
npm run build:prod  # 生产环境构建（启用压缩）
npm run deploy      # 构建并提示部署
```

### 4. 清理
```bash
npm run clean      # 清理dist目录
```

## 📦 构建输出

构建完成后，`frontend/dist/` 目录包含：
- `index.html` - 主页面
- `error.html` - 错误页面
- `assets/` - 静态资源（CSS、JS、图片）
- `build-info.json` - 构建信息

## 🔧 配置说明

### 环境变量
- `NODE_ENV=production` - 启用生产模式（压缩）
- `API_BASE_URL` - API基础URL
- `VERSION` - 版本号

### 模板变量
HTML文件中可以使用以下变量：
- `{{API_BASE_URL}}` - 会被替换为实际的API地址
- `{{VERSION}}` - 会被替换为版本号
- `{{BUILD_TIME}}` - 会被替换为构建时间

## 🚀 部署流程

1. **构建前端**：
   ```bash
   cd frontend
   npm run build:prod
   ```

2. **部署基础设施**：
   ```bash
   cd infrastructure/environments/test
   terraform apply
   ```

3. **验证部署**：
   - 检查COS存储桶中的文件
   - 访问CDN域名验证网站

## 📋 迁移说明

如果你之前使用了 `static-website/dist/`，现在需要：

1. **确认前端构建正常**：
   ```bash
   cd frontend
   npm run build
   ls -la dist/  # 确认文件存在
   ```

2. **删除旧目录**（可选）：
   ```bash
   rm -rf static-website/
   ```

3. **更新.gitignore**（如果需要）：
   确保 `frontend/dist/` 在 `.gitignore` 中（通常构建输出不提交）

## ⚠️ 注意事项

- 构建输出 `frontend/dist/` 通常不应该提交到Git
- 每次部署前都应该重新构建
- 生产环境务必使用 `npm run build:prod`
